# CheckScreenColor

画面上の一点を監視し、そこに鮮やかな緑が現れたらビープ音で知らせる .NET 8 / Windows Forms のユーティリティです。

進捗バーやステータスランプが緑になるのを、別の作業をしながら待ちたいときに使います。

## 使い方

1. アプリを起動すると、小さな半透明のウィンドウが最前面に表示されます。
2. タイトルバーをドラッグして、中央の四角い枠を監視したい場所に重ねます。
3. 枠の内側に対象の色が現れると、約 1 秒おきにビープ音が鳴ります。色が消えると鳴り止みます。
4. 終了するにはウィンドウを閉じます。

ウィンドウは常に最前面（`TopMost`）で、`#00FF00` を透過キーにしているため、枠の内側は背後の画面がそのまま見えます。

## 検出条件

100 ミリ秒おきに枠の内側をキャプチャし、1 ピクセルでも次の条件をすべて満たせば検出とみなします。

| チャンネル | 条件 | 定数 |
|:--|:--|:--|
| G | `> 200` | `MinTargetChannel` |
| R | `< 30` | `MaxOtherChannel` |
| B | `< 30` | `MaxOtherChannel` |

**この条件はかなり狭く、ほぼ純緑に近い色しか通りません。** 実測した例:

| 色 | RGB | 判定 |
|:--|:--|:--|
| `#00FF00` | (0, 255, 0) | 検出 |
| `#02FE04` | (2, 254, 4) | 検出 |
| `#00D000` | (0, 208, 0) | 検出 |
| `#00C800` | (0, 200, 0) | 不検出（G が `> 200` を満たさない） |
| `#1EFA28` | (30, 250, 40) | 不検出（R が `< 30` を満たさない） |
| `#22C55E` | (34, 197, 94) | 不検出 |
| `#00B050` | (0, 176, 80) | 不検出 |
| `#4CAF50` | (76, 175, 80) | 不検出 |
| `#008000` | (0, 128, 0) | 不検出 |

`#22C55E`（Tailwind の green-500）や `#4CAF50`（Material Design の緑）のように、UI で実際によく使われる緑はどれも通りません。**手元の対象色が検出されるかどうかは、上の条件に当てはめて確認してください。** 通らない場合は `MainForm.IsGreenish` のしきい値を対象色に合わせて書き換える必要があります。

ビープ間隔は `BeepIntervalTicks`、ポーリング間隔は `PollIntervalMs` で調整できます。

## 制約・既知の限界

- **監視領域の大きさは DPI に依存します。** 100% 表示では枠の内側は 5×5 ピクセルですが、フォントベースの自動スケーリングを使っているため高 DPI では拡大されます（150% 表示での実測値は 7×8 ピクセル）。
- **ロック画面や UAC の昇格ダイアログ（セキュアデスクトップ）が表示されている間は監視できません。** 画面のキャプチャ自体が拒否されるため、そのタイミングは見送られます（例外は捕捉してあり、アプリは落ちません）。
- **ハードウェアオーバーレイで描画されている領域は監視できません。** デスクトップの合成を経由せず直接出力される映像（一部の動画プレイヤーやゲームなど）は `Graphics.CopyFromScreen` で取得できず、黒などとして読み取られます。
- 監視できるのは 1 箇所だけです。複数箇所を同時に見たい場合はアプリを複数起動してください。
- ウィンドウの位置は保存されません。起動ごとに合わせ直す必要があります。
- 通知はビープ音のみです。音量が下がっていたり出力先が切り替わっていると気付けません。

## ビルド

Windows と .NET 8 SDK が必要です。

```
dotnet build -c Release
```
